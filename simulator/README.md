# Freight Malawi — Telemetry Simulator

A Node.js telemetry producer that stands in for ESP32 hardware, so the full
Freight Malawi platform can be demonstrated without physical devices.

It connects to the backend's `/device` Socket.IO namespace exactly the way
the ESP32 firmware does (device authenticates by `deviceId`), and sends the
same telemetry shape and via the same `telemetry` event.

## What it simulates

- 2–3 configurable trucks moving along the Lilongwe → Dedza → Zalewa →
  Blantyre (M1) corridor, interpolated between real waypoints, bouncing
  back and forth along the route.
- Realistic fuel consumption based on distance travelled and a
  per-truck efficiency (km/L), with small randomised variation so trucks
  don't behave identically.
- Periodic **simulated theft**: a truck stops, and its fuel level drops
  sharply (~20 L) while genuinely stationary across two consecutive
  telemetry packets — matching the backend's real theft-detection rule
  rather than just logging a message.
- Periodic **simulated refuelling**: a sudden +150 L increase.
- Automatic reconnection if the backend restarts or the connection drops.

## Setup

```bash
cd simulator
npm install
```

Edit `config.json`:

- `backendUrl` — where the backend is running (default `http://localhost:5000`)
- `tickIntervalSeconds` — how often telemetry is sent (default 5s)
- `theftIntervalMinutes` / `refuelIntervalMinutes` — how often each event fires
- `trucks` — each truck's `deviceId` **must match** the `deviceId` of a
  vehicle you've already created in the app (Vehicles page → Add Vehicle)

## Run

```bash
node simulate.js
```

You should see each truck connect, then periodic log lines for movement,
simulated theft, and simulated refuelling. Alerts appear on the dashboard
in real time as they're generated by the backend's rule engine — the
simulator does not create alerts itself, it only produces the telemetry
that causes the backend to create them.

## Notes

- Device IDs can be changed in `config.json` without touching `simulate.js`.
- To demo faster, lower `tickIntervalSeconds`, `theftIntervalMinutes`, and
  `refuelIntervalMinutes` — but keep in mind very short intervals mean the
  built-in per-truck stagger (used so trucks don't all trigger events at
  once) will be proportionally smaller as well, since it scales with the
  configured interval.
